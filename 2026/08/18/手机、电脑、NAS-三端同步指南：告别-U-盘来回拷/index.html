手机、电脑、NAS 三端同步指南：告别 U 盘来回拷

手上设备一多，文件同步就成了绕不开的麻烦。手机拍的照片想传到电脑，电脑写了一半的文档想在地铁上继续改，NAS 里下载的资源想在平板上看……曾经我的做法是微信文件传输助手加 U 盘来回倒腾，直到某天发现自己同时维护着三个版本的「最终版」文档，才下定决心把同步这件事认真做一次。

这篇文章不是要安利某个具体软件，而是把我折腾一圈后的选型思路整理出来：什么场景用工具，什么场景用脚本，什么场景干脆什么都别用。

同步的本质：先想清楚你要同步什么

动手之前，先回答三个问题，答案直接决定方案：

  1. 同步方向：是单向备份，还是双向实时同步？照片导出是单向，文档协作是双向。
  2. 冲突频率：同一个文件会不会在多个设备上同时被修改？会，就必须有冲突处理机制。
  3. 隐私等级：数据愿不愿意经过第三方服务器？私密文件最好走点对点方案。

把这三点写在纸上，再去看工具，你会发现选择瞬间清晰了很多。

场景一：文件双向同步，选 Syncthing

Syncthing 是我用得最久的一个。它开源、点对点、不经过任何服务器，设备之间直连加密传输，隐私这块让人放心。手机装 App、电脑装客户端，两端扫同一个二维码就完成配对，之后指定文件夹会自动保持同步，改动几乎是实时的。

它在 Termux 里也能跑，pkg install syncthing 装好，syncthing serve 启动，配合开机脚本就能把手机变成一个常驻同步节点。我的笔记文件夹和照片目录就挂在上面，手机拍完照，电脑上几秒内就能看到。缺点是需要设备同时在线（或至少一端在线），而且公网环境下的穿透配置对新手有点门槛，但局域网内使用体验已经足够好。

场景二：跨平台 + 云端兜底，用坚果云这类网盘

如果你需要 Windows、macOS、手机全平台覆盖，又不想折腾穿透，WebDAV 网盘类服务更省心。坚果云支持 WebDAV 协议，这意味着任何支持 WebDAV 的 App 都能直接读写云端文件——笔记软件、文件管理器、甚至脚本都能用 curl 操作。

一个很实用的玩法：把密码库、配置文件这类小体积但重要的数据，通过 WebDAV 挂在各端，改动自动上传，等于多了一份异地备份。缺点也很明显：免费流量有限，不适合大文件，而且数据经过第三方，敏感内容要提前加密。

场景三：代码和文档，交给 git

很多人忽略的一点是：git 本身就是最优雅的同步工具之一。它自带版本历史、冲突提示和回滚能力，文档类、代码类、甚至 Markdown 笔记库，用 git 同步比任何网盘都靠谱。

我的博客源码就是这个思路：手机 Termux 里编辑，git push 到 GitHub，Actions 自动构建部署。换设备？git clone 一下，几分钟就恢复全部环境。笔记库同理，Obsidian 或纯 Markdown 目录用 git 管理，配合 GitHub 私有仓库，历史版本随便翻。

场景四：不该同步的东西，用脚本归档

最后一个经验：不是所有东西都值得同步。下载的安装包、临时文件、缓存，同步它们纯属浪费流量和磁盘。我的做法是写个小脚本，定期把手机里需要归档的内容按日期打包，rsync 到 NAS，同步任务里只保留真正活跃的目录。

这类「归档式同步」不需要实时性，跑在 cron 里每天一次就够了，失败也不心疼，下次重跑即可。

总结

回顾下来，多设备同步没有银弹，但有一个清晰的决策路径：高频双向改动的文件用 Syncthing，需要全平台云兜底的小文件用 WebDAV 网盘，代码和文档交给 git，低频归档数据用脚本打包 rsync。四者组合使用，基本能覆盖日常所有场景。

关键不是工具本身，而是想清楚每个目录的性质再决定它该走哪条路。同步方案落地之后，最大的感受是：终于不用再问自己「最新版本到底在哪个设备上了」。
