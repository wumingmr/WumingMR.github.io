把书签扔进 SQLite：从浏览器导出到可查询的书签库

浏览器里的书签攒了上千条，想找三年前收藏的那篇博客，只能在层层文件夹里肉眼扫。搜索框只匹配标题，搜不到链接里的关键词；更别提统计”哪个域名收藏最多”这种事了。与其继续依赖浏览器自带的那套管理，不如把书签导出来，扔进 SQLite，想怎么查就怎么查。

导出：拿到 JSON 就成功了一半

Chrome / Edge / Brave 的书签本质是一个 JSON 文件，路径通常在：

文件没有扩展名，但内容就是标准 JSON。Firefox 则需要先通过「导入/导出」导出成 HTML，再用第三方库解析，稍麻烦一点，这里不展开。

拿 Chrome 的 JSON 结构来说，书签是一个递归的树：文件夹是 children，书签是带 url 字段的节点。递归遍历一遍，把每个书签的标题、URL、添加时间、所在路径抽出来就行。

进阶：让脚本定时跑

书签是会变的，浏览器导出的 JSON 也会跟着变。把导入脚本挂到 crontab 或者 Termux 的 termux-job-scheduler 里，每天凌晨重新导一次，库就永远是最新的：

再配合 fzf 做一个交互式模糊搜索，选中书签直接打开，终端里就能当书签管理器用了。

小结

浏览器书签本质上只是”树形结构的收藏列表”，能力天花板就在那里。把数据搬到 SQLite 之后，聚合统计、全文搜索、跨设备同步、死链清理，全都是几条 SQL 的事。整个方案没有引入任何第三方依赖，一个标准库脚本 + 一个 SQLite 文件，放在哪里都能跑。
